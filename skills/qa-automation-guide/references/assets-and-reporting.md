# Evidence, regression records, and defect reporting

## 目录与命名

以下路径均相对注入的 `WORK_DIR`：

| 资产 | 路径 | 命名 |
|---|---|---|
| 证据 JSON | `evidence_assets/{模块}/` | `{模块}_{场景}_asset.json` |
| 截图 | `evidence_assets/{模块}/` | `{YYYYMMDD}_{用例ID}_{步骤号}_{成功/失败/待定/超时/留证}.png` |
| 下载素材 | `downloads/{模块}/` | `{用例ID}_{业务对象}.{ext}` |
| 用例报表 | `output_testcases/` | `{模块}_{场景}.xlsx` |
| 测试报告 | `output_testcases/` | `{模块}_{YYYYMMDD}_测试报告.md` |
| VTable/筛选审计 | `artifacts/` | `{模块名}_筛选与列字段一致性缺陷_禅道BUG模板_{YYYYMMDD}.md` |

模块名与用例文档子表逐字一致；日期统一 `YYYYMMDD`；禁止 final/new/副本等无信息量后缀。

## 证据 JSON

每条用例至少记录：编号、名称、模块、步骤、数据、预期、结果、执行人、执行时间、备注、截图路径列表和失败详情。步骤定位器记录 `locator_type`、`locator_value`、`locator_extra`、`frame_path`。已有文件必须先读取并按用例编号合并，不能覆盖其他用例；同一用例保留最新结果并追加 `last_run`。

首轮资产是基线。回归只读基线，差异写新报告；定位器变化追加 `locator_history`。探查截图和临时文件不得混入资产目录。失败/待定必须截图；通过按任务要求决定是否留结果态截图。

## 测试报告

报告至少包含：汇总表（编号/名称/结果/执行人/时间/备注）、通过/失败/待定统计和通过率、回归状态翻转/新增失败、失败与待定的现场描述、证据路径。禅道 BUG 模板包含所属模块、标题、严重程度（1 致命/2 严重/3 一般/4 轻微）、优先级、类型、前置、复现步骤、预期、实际、影响分析、实测证据和截图。

VTable 审计还必须列出：筛选字段数量与清单、业务列数量与清单、名称映射、每个 `C ⊆ D` 的实测集合、通过项、数据范围和翻页补抽建议。

## 交付检查

- 证据全部来自实际工具返回，不补造数据；
- 失败/待定有截图和具体失败详情；
- 报告路径符合命名约定，VTable 审计落 `artifacts/`；
- 用例权威 JSON 与导出 xlsx 的来源关系清晰；
- 回归基线未被覆盖，状态翻转单独突出。
