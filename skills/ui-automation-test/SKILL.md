# 通用 UI 自动化测试执行任务（资产全生命周期）

> 调用方式：用户显式触发本技能（`/qa-automation-plugin:ui-automation-test`）并给出下列
> 占位符的实际值（测试用例文档 / 子表名 / 过滤字段 / 过滤值 / 系统 URL / 账号 /
> 执行人 / 证据根目录 / 报告路径 / Bug 系统 / 回归模式），未提供的参数保留占位符原文，
> 先向用户确认后再执行。一个场景一个文件（如 `vtable-数据校验`），互不干扰。

## 一、任务定义
对 {测试用例文档}（路径或附件）中的子表/工作表：{子表名}，按 {过滤字段} 过滤出
等于 {过滤值} 的全部测试用例，逐条调用 qa-automation 插件的能力执行 UI 自动化测试。
默认模式为**回归复验**：优先复用已有资产（见第六节），无资产时走首次录制（见第四节）。

## 二、执行前置
1. 被测系统：{被测系统 URL}；测试账号：{账号}（若未登录，先用 click_interact /
   fill_input 完成登录）
2. Chrome 以 --remote-debugging-port=9222 启动（插件经 CDP 接管本地 Chrome）
3. 用例文档列映射：{用例编号 / 用例名称 / 前置条件 / 测试步骤 / 测试数据 / 预期结果}

## 三、资产全景与命名规范（AI 可识别）

### 3.1 资产类型总览
| 资产 | 生成方式 | 位置（相对用户项目根） | 命名规范 | 用途 |
|---|---|---|---|---|
| 证据 JSON | export_session | evidence_assets/ | `{模块}_{场景}_asset.json` | 用例步骤 + 高韧性定位器 + 结果，**可复用驱动回归** |
| Excel 用例报表 | export_session | output_testcases/ | `{模块}_{场景}.xlsx` | 可执行用例库 / 交付物 |
| 截图 | capture_screenshot | evidence_assets/ | `{模块}/{日期}_{用例ID}_{步骤号}_{状态}.png` | 留证 / 失败分析 |
| 下载文件 | download_file | downloads/ | `{模块}/{用例ID}_{业务对象}.{ext}` | 数据核验素材 |
| 测试报告 | 模型生成（第六/九节规则） | output_testcases/ | `{模块}_{日期}_测试报告.md` | 汇总 / 提交 Bug 依据 |

### 3.2 命名原则（AI 与人都能一眼分辨）
1. **flow_name 规范**（直接决定证据 JSON 与 Excel 文件名）：`{模块}_{场景}`。
   模块 = 用例文档子表名（如 `基础配置`）；场景 = 动作 + 对象（如 `新增字典项`）。
   完整示例：`基础配置_新增字典项` → 产出 `基础配置_新增字典项_asset.json` / `基础配置_新增字典项.xlsx`。
   禁止使用"最终版 / final / new / 副本"等无信息量词；模块名与用例文档子表**逐字一致**。
2. **截图命名规范**：`{模块}/{日期YYYYMMDD}_{用例ID}_{步骤号}_{状态}.png`，
   如 `基础配置/20260808_TC001_02_保存成功.png`。状态词用固定集合：
   `成功 / 失败 / 待定 / 超时 / 留证`。用例 ID 与用例文档编号逐字一致（TC001 等），
   保证 AI 检索时可从文件名直接还原"哪个模块哪条用例哪一步什么结果"。
3. **报告命名**：`{模块}_{日期}_测试报告.md`，如 `基础配置_20260808_测试报告.md`。
4. 日期统一 `YYYYMMDD`；文件名内不用空格（工具已自动转下划线，传参时直接写规范名）。

## 四、资产生成 SOP（首次执行 / 新用例）
每条用例按"分析 → 执行 → 验证 → 留证"四步，并**在动作发生处同步生成资产**：
1. **录制会话**：调 start_recording 开启会话，`flow_name` 用 3.2 规范名
   （如 `基础配置_新增字典项`）；system_under_test 填被测系统标识。
2. **执行并记录**：每一步用 execute_and_record 执行，`description` 写"动作 + 对象"
   （如 `点击保存按钮`），`expected_result` 写该步断言预期——这两字段是资产可复用
   与自动判定的核心，**禁止留空**。
3. **关键节点截图**：capture_screenshot 显式传规范文件名（见 3.2），每个用例至少
   一张"结果态"截图；失败/待定步骤必须截图。
4. **导出资产**：全部步骤完成即调 export_session → 生成证据 JSON + Excel。
   JSON 的 steps[] 中 locator_type/locator_value/locator_extra/frame_path 为录制时
   验证过的高韧性定位器，是后续回归的"免重分析"资产。
5. **下载素材**：涉及下载核验时用 download_file 指定规范文件名，落 downloads/。

## 五、资产管理规则
1. **追加合并，绝不覆盖**：证据 JSON 已存在时，先读取 → 按用例 ID 合并 → 整体写回；
   同用例保留最新结果并附 `last_run` 字段，历史结果不删除。
2. **目录按模块组织**：截图与证据的模块子目录名与用例文档子表逐字一致；禁止把
   多个模块的资产混入同一目录。
3. **失败强制留档**：不通过 / 待定用例必须产出：截图（结果态）+ 失败详情字段；
   通过用例仅留证据 JSON 记录。
4. **基线资产**：首轮完成的资产集即"基线"。回归测试只读基线、不修改基线文件；
   差异写入新报告与合并后的 JSON（保留 last_run 对比）。
5. **清理规则**：探查性截图（probe/wait 复核用）不入资产目录或直接删除；资产目录
   只保留符合 3.2 命名的结构化文件；临时文件落系统临时目录。

## 六、资产复用与回归测试（默认执行路径）
回归复验**优先复用资产，不做重复劳动**：
1. **定位器复用（免重分析）**：读取基线 `{模块}_{场景}_asset.json`，其 steps[] 的
   locator 字段（locator_type / locator_value / locator_extra / frame_path）可直接
   构造 execute_action_chain 步骤执行——跳过 analyze_current_page 重新分析；
   仅当动作执行失败（定位超时/元素不存在）时，才回退 analyze_current_page 探查
   新定位器并更新资产。
2. **基线对比**：逐条用例对比本次结果与基线 JSON 的 `测试结果`，报告分类输出：
   状态翻转（通过→失败 / 失败→通过）、新增失败、保持通过/失败。**状态翻转是
   回归最高优先级信号**，必须给出截图与失败详情。
3. **增量回归策略**：用户指定 {回归模式}：
   - 全量回归：过滤条件下全部用例。
   - 冒烟回归：每条用例仅执行核心步骤（首个断言动作 + 结果态截图）。
   - 模块回归：仅 {子表名} 指定模块的用例（默认，与过滤值一致）。
   未指定时默认模块回归。
4. **资产回填**：回归结果按第五条合并规则写回证据 JSON（追加 last_run），
   定位器更新（页面改版后新定位器替换旧值）必须保留旧值于 `locator_history`。
5. **Excel 用例库**：output_testcases/ 下的 xlsx 即"可执行用例库"，回归前核对
   列映射与用例文档一致；不一致时以用例文档为准并提示用户。

## 七、测试结果判定（逐条，互斥）
- 通过：页面数据信息与流程符合"测试步骤 + 测试数据 + 预期结果"
- 不通过：出现至少 1 点与预期结果不符
- 待定：用例自身信息（步骤/数据/字段）与页面实际不符，或环境问题导致无法
  完成验证、无法判定对错
回填规则：测试结果（下拉：通过/不通过/待定）；执行人={执行人}；执行时间=当前
系统时间；备注（通过：留空；不通过：简要失败原因；待定：说明哪一步骤/哪个
数据/哪个字段与页面不符）。

## 八、执行方式（动作链优先）
每条用例按"分析 → 执行 → 验证 → 留证"四步：
1. 优先复用资产定位器（第六节）；无资产时 analyze_current_page 分析页面结构
2. execute_action_chain 批量执行步骤（click/fill/select_option，依赖动作级
   fallbacks 容错）
3. wait_for_condition 验证关键反馈（成功提示/元素出现），必要时
   probe_dynamic_layers 复核浮层；VTable 表格场景用 vtable_* 工具读取数据断言
4. 关键节点 capture_screenshot 留证（文件名按 3.2 规范）
失败处理：动作失败先读返回的错误（定位超时/元素不存在/严格模式多匹配），用
probe / wait_for_condition 复核页面实况，不盲目重试同一动作；定位器失效时
按第六节更新资产。

## 九、证据资产保存（每测完一条立即执行）
1. JSON 证据：{证据根目录=项目根 evidence_assets}/{模块}/{模块}_{场景}_asset.json
   - 不存在则创建；存在则先读取、合并、再整体写回（追加，绝不覆盖）
   - 每条记录字段：用例编号 / 用例名称 / 模块 / 测试步骤 / 测试数据 /
     预期结果 / 测试结果 / 执行人 / 执行时间 / 备注 / 截图路径列表 / 失败详情
   - 回归场景额外维护：last_run（本次时间/结果）、locator_history（定位器变更史）
2. 截图：测试结果为"不通过 / 待定"时必须 capture_screenshot 留证（含页面
   状态与关键元素），路径写入该记录的"截图路径"字段；"通过"不强制。

## 十、测试报告（全部用例测完后）
基于上述 JSON 生成 Markdown 报告，保存至 {报告路径=output_testcases/
{模块}_{日期}_测试报告.md}：
- 汇总表：用例编号 / 名称 / 结果 / 执行人 / 执行时间 / 备注
- 统计：通过 / 不通过 / 待定数量与通过率
- 回归对比：与基线对比的状态翻转 / 新增失败清单（仅回归模式）
- 重点章节：不通过、待定用例逐一给出失败原因、截图、现场描述
- 文档末尾：每个不通过 / 待定用例按 {Bug 系统=禅道} 提交规范给出模板
  （标题 / 优先级 / 所属模块 / 前置条件 / 重现步骤 / 实际结果 / 预期结果 /
   附件截图 / 环境信息）；标题直接用规范命名（如 `[基础配置] TC001 新增字典项保存失败`）

## 十一、汇报节奏
每自动化测试完一条用例，立即汇报该条执行情况（用例编号 / 名称 / 结果 /
关键证据路径），等待我确认后再执行下一条。回归模式下同一条规则，状态翻转
用例优先汇报并附截图。
